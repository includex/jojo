# 임충전 콘텐츠와 네이티브 모드 검증 기록

이 모드는 기존 조조전의 Python AST 시나리오·BattleScreen·전투 메뉴를 사용한다. `campaign.json`은 원안 보존·생성을 위한 중간 자료이며 별도 전투 실행기가 아니다. `source.md`가 제공받은 전체 PRD다.

## 원안 데이터 검사

`python3 scripts/import_linchong.py`와 `python3 scripts/validate_linchong.py`는 다음을 확인한다.

- 8전투, 70개 초기/증원 배치, 79이벤트, 이벤트 대사 217줄, 조건 대사 13줄, 인터루드 34줄.
- 등장인물 10, 시작 장착 7, 무공 8, 아이템 18, 원안 QA 요구사항 20개.
- 모든 원안 이벤트 대사가 원문에 존재하고 1-base 좌표·최대/현재 HP를 보존한다.
- 증원 이벤트 참조, 좌표 범위, 제작 보완 지형의 배치 충돌과 상호작용 지점 접근성.

원안 데이터 검사는 조조전 전투의 실제 완주나 밸런스 검증을 대신하지 않는다.

B01/B05/EX02는 적 전멸만으로 자동 승리하면 원안의 탈출·확보 목표가 생략된다. 기존 엔진의 자동 전멸 승리를 방지하도록 숨긴 정지 적 개체를 차단 타일에 두며, 최종 승리는 시나리오의 명시적 보상 결과로 처리한다. 원안의 마지막 허용 턴을 전부 플레이하도록 네이티브 최대 라운드에는 원안 제한+1을 전달한다.

## 그대로 구현하지 않은 원안 전용 기능

다음은 원안 자료에 보존되며, 별도 전투 엔진으로 대체하지 않았다.

- 액티브 3/패시브 2/심법 1 슬롯, 전투별 숙련 상한·4/10/18 강화, 별도 성장 포인트·칭호·인연/도감 상태 체계.
- BOUND/DISARMED/INJURED/SPARRING/NONLETHAL 같은 원안 전용 상태의 동일 수치·사망 방지 보장. 비살상 결투는 기존 일기토 연출과 항복 HP 이벤트로 각색한다.
- 임의 +3 공격/+10 명중을 정확히 두 턴만 적용하는 원안 버프. 기존 직업·장비·기술 효과를 사용한다.
- 눈길 -1 이동과 설중정심의 전용 면역, 물가 전용 이동 보너스 등 원안 전용 계산식의 완전한 재현.
- 전장 위 새 장수/무공/장비/가방/도감 패널과 행동을 소비하는 전용 장비 교체 규칙. 기존 조조전 UI를 유지한다.
- 모든 원안 FX/tip/reveal/발자국 표시 명령. 해당 사건의 대사는 유지한다.
- 원안의 별도 이벤트/보상 ID 영속 저장·체크포인트 롤백 체계. 기존 게임의 저장과 승리 저장 흐름을 사용한다.

일반 유효 적중처럼 기존 시나리오 API에 직접 콜백이 없는 튜토리얼은 턴 조건으로 옮겼다. B06의 동료 직접 공격 제한은 허정·진오를 비조작 우군으로 배치하여 표현한다. 원안의 기하 설명에서 빠진 건물 외곽과 2차 화염 6칸은 출입·우회를 보존하도록 제작 보완했다.

## 네이티브 스크립트 검사

`python3 scripts/build_linchong_mod.py`와 `:core:exportScenarioAst`로 기존 AST 계약을 검증한다. 고정 대사 미참조 ID는 남기지 않는다.

`LinchongNativeScenarioTest`는 실제 `ScenarioInterpreter`를 사용한다. 전투 문맥의 HP·좌표를 조건별 고정 입력으로 공급하므로, 실제 이동/공격을 통한 완주 검사가 아니다. 검사 범위는 8전장 초기화, 구출, 장물/창고 조건, 보상·기술 지급, 선택 전투 생략, 허정 영입 수락/거절, 진오 영입, 두 명 탈출, 주인공 패배 우선, 최종 완료 후 재시작 방지다.

실행:

```sh
./gradlew :verification:campaignUnitTest --tests '*LinchongNativeScenarioTest'
```

전체 `:verification:test`에는 별도 원본 추적 도구(Node)가 필요한 검증도 연결되어 있다. 위 집중 테스트는 저장소의 기존 독립 캠페인 테스트 작업을 사용한다. 실제 화면 로드·대사·입력 검증은 별도의 네이티브 시각 스모크 결과를 확인해야 하며, 모든 전투를 조작해 완주했다는 주장과 구분한다.

## 기존 조조전 모드 구현 검증 (2026-11-01)

- 운영 `engine/`, `core/`, `desktop/`, 콘텐츠 컴파일러 변경 없음.
- 기존 ScenarioInterpreter를 실행한 11개 조건·보상·영입·경로·초기 장비·완료 메뉴 테스트 통과.
- 기존 JojoGame/BattleScreen으로 S_90~S_97 전체 전투 진입 통과. 첫 전투는 턴 종료 입력과 노지심 증원까지 확인.
- 생성 에셋 94개 포맷 검사, 대사 AST 내보내기 및 콘텐츠 컴파일 통과.
- PRD 자료의 규칙 전부를 새로운 엔진으로 구현한 것은 아니다. 실제 각색 범위는 README와 native-content-mapping.json을 따른다.
- 모든 전투의 수동 완주·난이도 균형·장시간 저장/불러오기 플레이테스트는 아직 완료하지 않았다.

현재 집중 테스트는 11개다. 새 게임은 기존 CampaignState.reset()을 거쳐 명명 전역 변수도 초기화한다. 전투 중 저장 복원은 기존 조조전의 저장 경로를 사용하며, 임의로 같은 CampaignState에 S 시나리오만 새로 로드하는 개발용 재시작은 지원하지 않는다. 이를 위해 영속 진행 플래그를 임의로 초기화하는 별도 로직을 추가하지 않았다.

## 스프라이트 2차 제작 검증

- 16종 × 공격 12 + 이동·피격 11 + 특수 5 = 448개 생성 포즈를 기존 48개 캐릭터 아틀라스에 패키징했다.
- 공격 아틀라스는 모두 12개 서로 다른 프레임이며, 64×64/66px pitch와 48×48/50px pitch를 유지한다. 기존 battle-anime.json은 변경하지 않았다.
- 배경 알파, 프레임 분리, 투명 행 여백, 좌우 방향을 검사했다. 겹친 무기·누락된 뒤쪽 걷기는 이미지 생성 도구로 다시 제작했다. 인물 크기는 표시 크기에서 비교하고 조정했다.
- 기존 런타임의 공격 4단계·좌우 반전 렌더 캡처와 S_90 실제 공격·반격·노지심 증원 검증을 통과했다.
- 새 작화는 작은 픽셀 스프라이트 표현을 따르지만 원본보다 명암·세부 묘사가 많다. 구조 일치와 화풍의 완전한 동일성은 구분한다. 비교 문서: docs/linchong-sprite-review.html.
- 생성 방식: built-in image_gen. 정확한 프롬프트와 수정 이력: assets/sprites-v2/provenance-*.json.

## 사용자 피드백 후 스프라이트 정렬 재검토

- 이전 파일 규격·프레임 수 검증은 공격/이동 전환의 크기와 발 위치를 검증하지 못했다. 검토 HTML과 단독 캡처 도구가 서로 다른 크기의 셀을 같은 화면 크기로 늘려 문제를 숨긴 점을 수정했다.
- `framing.json`으로 배율과 프레임 기준점을 명시한다. 공격 셀의 아래 8px 여백을 확보하여 이동 셀과 바닥이 이어지도록 하고, 무기 끝을 발로 취급하는 프레임을 보정한다.
- 새 검토 페이지의 기본 재생은 대기 → 공격 → 대기이며, 원본과 신규 아틀라스를 같은 픽셀 배율로 표시한다. 시트 작화 자체의 자세·의복 변화는 정렬과 별도로 시각 검토해야 한다.

## 조조전 작화 기준에 따른 3차 제작

- 사용자 제공 원본 게임 화면을 `assets/sprites-v3/style-reference.png`로 보존했다. 기존의 큰 머리·둥근 만화풍을 수정하기 위해 16인 전체를 새로 생성했다. 임충 시트를 공통 참조로 사용하여 작은 머리, 성인 비율, 복장과 무기를 프레임 전체에서 유지하도록 지시했다.
- 원본은 built-in image_gen으로 생성하고 정확한 프롬프트와 생성 경로를 `provenance-parent.json`, `provenance-a.json`, `provenance-b.json`에 기록한다. 생성 이미지의 실제 크기가 요청 크기와 다르므로 투명 여백을 기준으로 분리하며 고정 해상도를 가정하지 않는다.
- 엔진의 타임라인과 슬롯 수는 변경하지 않는다. 게임에 적용하는 48개 아틀라스는 새 시트와 새 `framing.json`에서 다시 생성한다. 원본 작화와의 완전한 동일성을 자동 검사로 단정하지 않는다.

- 3차 패키징 검증: 16인 × 28프레임의 알파 범위·아틀라스 슬롯·투명 행 여백·원본 해시 검사를 통과했다. 야저림을 실제 BattleScreen으로 실행하여 공격·반격 및 노지심 등장 이후 진행을 확인했다. 검토 HTML의 JavaScript 구문 검사도 통과했다.
