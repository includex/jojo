01 / execution boundary

Python 모양의 콘텐츠, Kotlin이 실행하는 계약

이 프로젝트는 CPython을 내장하지 않습니다. Python 소스를 JSON AST로 내보내고 engine이 지원하는 문법만 실행합니다. 아래 명세는 원본 게임의 모든 Python 기능이 아니라 현재 저장소의 디스패처가 처리하는 호출 계약입니다.

S: 전투
② 빌드export_python_ast.py
대사 ID 검증
복원 분기 보정
③ 실행engine/script

API 이름을 추측해 호출하지 마세요. 미등록 호출은 예외 대신 unhandledCalls에 기록되고 0을 반환할 수 있습니다. 원본에 있는 호출도 현재 구현 지원 여부를 확인해야 합니다. 아래 검색 결과의 제한 사항과 소스 링크가 기준입니다.

02 / conventions

명세를 읽는 방법

표기의미
signature의 = 값구현에서 명시적으로 사용하는 기본값. 인자는 위치 순서대로 전달합니다. 현재 평가기는 키워드 인자를 처리하지 않습니다.
반환 0 / null대부분 명령의 처리 결과용 값입니다. 성공 여부를 뜻하지 않습니다.
대기 / 조건부 대기다음 문장 실행이 입력·시간·화면 콜백까지 중단됩니다. 전투 외부 연출 연결 여부에 따라 달라질 수 있습니다.
원시 코드·flags원본 호환 숫자입니다. 설명이 없는 비트를 임의로 조합하지 말고 사용 위치와 구현을 함께 확인합니다.
사용 예특정 맵·인물·함수 상태를 전제로 하는 호출 예입니다. 완전한 독립 실행 시나리오를 의미하지 않습니다.

호출별 구현 파일과 실제 사용 위치를 함께 연결했습니다. 함수 호출 횟수는 119개 작성 소스의 정적 AST 집계이며 실행 횟수가 아닙니다. 중첩된 stage.unit(...)도 별도 호출로 집계합니다.

03 / suspension model

다음 줄은 언제 실행될까?

아래 상태를 선택하면 호출과 재개의 관계를 볼 수 있습니다. 실제 타이머를 재현하는 시뮬레이터가 아닌 실행 계약 설명입니다.

RUNNING → 상태 변경 → 다음 문장

예: model.addMoney(100). 화면 입력을 기다리지 않고 게임 상태를 변경합니다.

RUNNING → DIALOGUE / INFO → 완료 → 재개

stage.say('@dialogue:ID')가 문장을 찾습니다. & 화자 표식이 있으면 대화, 없으면 정보 표시 경로입니다. 첫 확인은 글자 공개, 이후 확인은 페이지 진행으로 이어집니다.

RUNNING → CHOICE → 선택 확정 → 대입 → 재개

answer = stage.choice('출진\n대기', 0)의 결과는 1 또는 2입니다. UI·trace 선택 인덱스는 0 또는 1입니다. 일반 함수 반환과 달리 AST의 대입문을 가로채어 확정 뒤 결과를 넣습니다.

RUNNING → DELAY / 외부 연출 → 완료 신호 → 재개

stage.delay(10)의 단위는 0.1초 tick이며 첫 update 준비 규칙도 적용됩니다. 이동·애니메이션은 화면 콜백을 기다리기도 합니다. 숫자를 모두 초 단위로 해석하면 안 됩니다.

05 / authoring recipes

작은 변경부터 연결하기

대사 한 줄 추가

  1. 카탈로그 entries에 미사용 고정 ID를 등록합니다.
  2. 실행되는 scene 함수에서 같은 ID를 호출합니다.
  3. AST를 내보내고 화자·페이지 진행을 확인합니다.
# content/scenarios/R_01.py의 실행되는 함수
stage.say('@dialogue:R_01.scene1.recruit_greeting')

# dialogue-text.json의 entries에 추가할 항목
"R_01.scene1.recruit_greeting": "&512\n주군, 명을 내려주십시오."

인물 512를 먼저 등록한 예입니다. ID는 예시이며 중복이면 새 이름을 고릅니다. 위 JSON 항목은 Python에 붙여 넣지 않습니다.

선택 결과로 분기

answer = stage.choice('출진한다\n준비한다', 0)
if answer == 1:
    stage.info('출진을 준비합니다.')
else:
    stage.info('장비를 점검합니다.')

현재 단순 대입 형태를 사용합니다. 선택 호출을 복잡한 수식 안에 넣지 않습니다. stage.ask는 별도 if 조건 가로채기 계약이 있으므로 아래 상세 스펙을 확인합니다.

기존 전투를 수정하는 순서

scene0초기화·배치·맵·시작 연출
scene1턴·진영·위치 조건과 증원
scene2종료·보상·복귀 조건
검증첫 턴 → 조건 이벤트 → 승패 → 복귀

이 역할은 기존 S 모듈의 구성 관례입니다. 함수가 이름만으로 자동 실행되는 것은 아니며 __dispatch__와 호출 지점을 함께 확인합니다. 전체 전투 예시는 S_00.py를 기준으로 작은 변경을 적용하세요.

06 / language limits

영역작성 규칙
문법표현식·대입·복합 대입·if·for·return 중심의 제한된 AST 실행입니다. import, class, while, 예외 처리, 일반 라이브러리 사용을 지원한다고 가정하지 마세요.

연산정수 중심 Add/Sub/Mult/Mod/LShift/BitOr, 비교 Eq/NotEq/Lt/LtE/Gt/GtE/In 등을 처리합니다. 나눗셈·복합 비교 등의 일반 Python 의미를 보장하지 않습니다.

컨테이너리스트/튜플 리터럴과 사전 리터럴을 처리하지만 첨자 읽기는 정수 인덱스 중심입니다. 사전 리터럴은 문자열 키로 생성되므로 범용 Python dict 연산을 기대하면 안 됩니다.
