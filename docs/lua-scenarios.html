Lua로 시나리오 작성하기

실행 시나리오는 content/scenarios/R_90.lua~R_97.lua, S_90.lua~S_97.lua에 있습니다. 동일 모듈의 Lua 파일이 있으면 Lua를 실행합니다. Python 파일과 AST는 이전 언어와의 비교·호환용으로만 사용할 수 있습니다.

① 콘텐츠 정의

인물·아이템·스킬은 기존 YAML에 정의합니다. Lua는 이 ID를 참조해 사건과 연출을 구성합니다.

② 사건과 대사 작성

시작 장면은 scene0, 전투 중 사건은 scene1에 작성합니다. 진행 플래그로 사건이 한 번만 실행되도록 합니다.

③ 빌드와 실행 검증

Lua 원본은 리소스로 복사됩니다. 게임 화면에서 대화·이동·공격 완료 후 다음 명령이 이어지는지 확인합니다.

1. 기존 장면을 복사하기

가장 가까운 .lua를 복사하고 모듈 이름, 게임 경로 설정, 인물·지도 ID를 변경합니다. R_는 장간 장면, S_는 전투 장면의 현재 패키지 관례입니다. 번호를 변경할 때는 game.yaml과 manifest.json도 함께 확인합니다.

2. 대사 작성하기

function scene0()
    stage.say("@dialogue:S_90.B01_E02.line002")
    stage.say("&513\n임 형제, 내가 왔네!")
end

@dialogue:로 시작하면 dialogue-text.json에서 해당 ID를 조회합니다. 그 외는 입력 문구를 그대로 표시하며 &513은 기존 화자 지정 문법입니다. 새 언어 파일로 옮겨도 대사 ID를 바꾸지 않습니다. 없는 ID는 오류이므로 카탈로그 항목도 함께 작성해야 합니다.

3. 진행 상태로 중복 실행 막기

function scene1()
    if gvars["linchong.example_event"] == 0 then
        gvars["linchong.example_event"] = 1
        stage.giveUnitItem(513, 216, 4)
        stage.say("&513\n금창약을 챙겨 왔네.")
    end
    return false
end

새 키는 content/variables/globals.yaml에 먼저 정의합니다. Lua에서 숫자 0은 참으로 취급됩니다. Python의 if flag:를 그대로 옮기지 말고 정수 플래그라면 flag ~= 0, 실행 전 검사는 flag == 0처럼 명시합니다. vars[0] 등 기존 숫자 키는 0부터 시작하는 게임 계약을 유지하며 Lua 배열 관례에 맞춰 임의로 1을 더하지 않습니다.

4. 인물 배치와 공격 연출

stage.createMine({
    {id=513, i=5, idx=5, x=1, y=7, lv=3, dir=1, ai=2}
})
stage.unit(513).setAction(6, 1, false)
stage.unit(513).setAction(7, 1, false)
stage.unit(513).setAction(0, 1, false)

좌표와 ID는 기존 stage API와 같습니다. Lua에서 API는 예제처럼 점(.)으로 호출합니다. 다만 end는 Lua 예약어이므로 장면 종료는 stage["end"]()로 작성해야 합니다. stage.unit(513)은 해당 인물 참조를 반환합니다. 방향은 북쪽 0·동쪽 1·남쪽 2·서쪽 3입니다. setAction은 연출이며 자체적으로 전투 피해를 주지 않습니다. 실제 화면에서 대화나 비반복 연출을 시작하는 API는 완료 시점까지 시나리오를 대기시킨 후 다음 명령을 실행합니다.

5. 문법 차이 확인하기

이 게임은 생성기가 Lua 실행 원본과 Python 비교용 원본을 함께 다시 작성합니다. Lua 파일을 수정하면 다음 빌드에서 해당 Lua가 실행되지만, 생성기를 재실행하면 수정 내용이 덮어써집니다. 영구 수정은 생성기와 제작 원본에 반영하고 결과 파일도 함께 확인하세요. 기존 저장 namespace와 대사·인물·아이템 ID를 유지했으며, 이전 Python 실행 중의 임의 명령 위치를 Lua 명령 위치로 자동 변환하는 기능을 뜻하지는 않습니다. 장면 진입과 사건 플래그를 기준으로 저장·복원 동작을 검증합니다.
