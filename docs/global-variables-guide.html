이름 있는 시나리오 전역 변수

문서 홈 · 시나리오 플랫폼 · 게임 규칙 확장 · 2026-11-01

새 진행 상태는 gvars["campaign.current_chapter"]처럼 의미 있는 이름으로 읽고 씁니다. 이름·타입·기본값은 콘텐츠에 선언하고, 기존 숫자 주소는 필요한 항목에만 별칭으로 연결합니다. 이름은 저장 파일에 남는 식별자입니다.

① YAML 선언② 시나리오 사용③ 저장 호환성④ 검증

1. 콘텐츠에 이름과 기본값 선언

작성 원본은 content/variables/globals.yaml입니다. version: 1 아래 variables는 변수 이름을 키로 하는 매핑입니다. 현재 두 선언은 실제 변환된 시나리오에서 사용합니다.

version: 1
variables:
  campaign.current_chapter:
    type: int
    default: 0
    description: 현재 캠페인 장 번호
    legacyId: 4057
  ui.feats_enabled:
    type: int
    default: 0
    description: 공훈 표시 활성화 상태
    legacyId: 4074

새 불리언 상태는 같은 variables 아래 다음 항목을 추가할 수 있습니다. 이 항목은 작성 예시이며 기본 콘텐츠에 자동으로 등록되지 않습니다.

  story.met_emperor:
    type: bool
    default: false
    description: 황제를 만났는지 여부
필드작성 규칙
변수 이름namespace.snake_case 형식. 점으로 구분한 각 부분은 영문 소문자로 시작하며 소문자·숫자·밑줄을 사용합니다. 점이 하나 이상 필요합니다.
typeint 또는 bool만 지원합니다.
default타입과 일치하는 정수 또는 불리언이 필수입니다. int의 "0", 소수, true와 bool의 0은 허용하지 않습니다.
description비어 있지 않은 설명이 필수입니다. 값의 의미와 변경 시점을 적습니다.
legacyId선택 필드. 기존 숫자 주소를 연결할 때만 0 이상의 정수를 지정합니다. 변수 간 중복 별칭을 사용할 수 없습니다.

2. Python 시나리오에서 읽기·쓰기

# int 읽기, 대입, 복합 대입
chapter = gvars["campaign.current_chapter"]
gvars["campaign.current_chapter"] = 1
gvars["campaign.current_chapter"] += 1

# 위 bool 예시를 YAML에 추가한 뒤 사용
if not gvars["story.met_emperor"]:
    gvars["story.met_emperor"] = True

선언하지 않은 이름의 읽기와 쓰기는 오류입니다. 이름 기반 대입은 타입을 엄격히 검사합니다. int에 True를 넣거나 bool에 1을 넣을 수 없습니다. 복합 대입은 정수 변수에 사용합니다. YAML 불리언은 true/false, Python 시나리오 불리언은 True/False로 작성합니다.

gvars["campaign.current_chapter"] = 3
# legacyId가 같은 저장 상태를 가리키므로 gvars[4057]도 3

gvars[4057] = 4
# 이제 gvars["campaign.current_chapter"]도 4

숫자 별칭과 이름은 동일한 상태를 공유합니다. bool 변수에 별칭을 지정했다면 이름으로는 불리언, 숫자 주소로는 0/1을 사용합니다. 다른 숫자는 거부합니다. 선언되지 않은 기존 숫자 주소의 접근은 호환 경로로 계속 허용합니다. 새 변수에는 이름을 선언해서 사용하세요.

현재 Python 소스를 빌드에서 AST로 내보내고 Kotlin 실행기가 처리합니다. CPython이나 Lua로 실행하지 않습니다. 전투 규칙용 Lua는 별도로 제공하며, 시나리오의 gvars와 자동 연결되지 않습니다.

3. 저장 형식과 이전 저장 파일

새 저장 파일은 이름 있는 값을 namedGlobals에 기록합니다. 숫자 별칭을 가진 값도 이름으로 한 번만 저장하며, globals에는 이름이 없는 기존 숫자 값만 남깁니다. 다음은 전체 저장 파일이 아닌 관련 필드의 예시입니다.

{
  "namedGlobals": {
    "version": 1,
    "values": {
      "campaign.current_chapter": 4,
      "ui.feats_enabled": 1
    }
  },
  "globals": { "1234": 7 }
}

namedGlobals가 없는 이전 저장 파일도 읽습니다. globals의 숫자 주소가 현재 선언의 legacyId와 일치하면 해당 이름의 값으로 복원합니다. 저장 파일에 없는 이름은 YAML 기본값을 사용합니다. 따라서 새 변수를 추가할 때 이전 저장 파일에서 쓸 기본값을 신중하게 정하세요.

알 수 없는 이름, 잘못된 타입·버전, 숫자 별칭과 이름의 값 충돌은 복원을 거부합니다. 같은 변수의 숫자 값과 이름 값이 함께 있으면 서로 일치해야 합니다. 전역 변수와 확장 상태를 적용 전에 검증하므로, 이 영역의 오류가 발견되면 캠페인 상태를 변경하지 않고 복원을 거부합니다.

배포한 이름은 영속 식별자입니다. 이름을 바꾸거나 삭제하려면 이전 저장 값의 마이그레이션이 필요합니다. 현재 지원하는 호환 처리는 숫자 별칭 복원이며, 임의의 이름 변경을 처리하는 범용 마이그레이션은 아직 없습니다.

4. 게임 규칙 확장 자원과의 관계

gvars는 시나리오의 진행 상태입니다. rules/game-rules.yaml의 자원과 저장 파일의 extensionState는 게임 규칙 확장의 상태입니다. 두 저장 영역은 별개이며 같은 이름을 적어도 자동으로 연결되지 않습니다. 내공 같은 규칙 자원은 게임별 규칙 확장 계약의 경로를 사용합니다.

5. 수정 후 확인

./gradlew :core:compileGameContent :core:exportScenarioAst
./gradlew :engine:test :core:test
./gradlew :verification:verifyAllHeadless

일반 리소스 빌드에서도 YAML을 컴파일합니다. 생성된 데이터 대신 content/variables/globals.yaml과 시나리오 원본을 편집합니다. 새 선언은 기본값에서 시작하는지, 이름과 숫자 별칭이 서로 반영되는지, 이전 저장 파일을 열 수 있는지 확인합니다.
