게임 패키지 분리 반영

content/game.yaml로 시작·주인공·저장·전투 연결을 설정하고, 14개 게임 테이블·문구·번역·실행 자산을 content에서 관리합니다. 패시브 125개와 능동 책략 37개 효과 바인딩을 의미 이름으로 분리했습니다. 일반 빌드는 외부 복원 프로젝트를 요구하지 않습니다.

게임별 규칙 확장

RuleHandler/RuleModule, 턴 시작·일반 물리 피해 보정·행동 완료 후크, 검증된 효과 적용, 이름 공간별 자원과 난수 상태 저장을 추가했습니다. 기본 게임은 추가 규칙 비활성 상태를 유지하며 내공 회복은 예제 설정으로 제공합니다. 외부 Lua 규칙과 ATTACK/HIT의 공격력·피해 보정, 활성 진영의 TURN_START/END를 연결했습니다. 장수·실제 착용 장비별 바인딩을 지원하며 2차 반사/반동 등은 제외됩니다.

구현된 구조

engine / core 분리

engine은 AST 실행·격자 경로 탐색·글자 공개·그래픽 계산을 소유합니다. core는 게임 데이터·전투 규칙·시나리오 의미·입력·화면·저장·번역을 담당합니다. 엔진에서 게임 모듈을 참조하지 않는 경계를 빌드가 검사합니다.

공통 대화 처리

전투·거리·궁전의 상태 변환과 글자 공개·확인·자동 진행은 공통 대화 세션을 사용합니다. 배치·자산·타이밍 정책은 장면별로 유지합니다.

콘텐츠 작성

인물·장비·스킬을 개별 YAML로 작성하고 buildSrc가 검증하여 런타임 테이블로 변환합니다. 런타임은 YAML을 직접 읽지 않습니다. 시나리오의 초기 전투 배치는 여전히 S_XX.py의 사전 목록에 있습니다.

시나리오 플랫폼 준비

대사 고정 ID를 소스에서 명시하며 entries에 문장을 등록합니다. 줄 삽입·함수 이름 변경·모듈 이동에도 ID를 유지합니다. legacyKeys는 이전 줄 번호 키를 연결합니다. ScenarioHostApi v1은 say·delay·choice를 정의합니다.

검증 기록의 범위

앞선 구현 작업에서 엔진·코어 테스트, 데스크톱·Android·verification 컴파일, 전체 헤드리스 검증이 통과했습니다. 고정 ID 마이그레이션은 대사를 실제 문장으로 해석해 비교했을 때 119개 생성 AST가 기존 버전과 동일했습니다. 이후 빈 선택지 거부는 별도 호스트 API 테스트로 확인했습니다.

  • 헤드리스: R 59개 기동·한 입력 분기, S 58개 초기화·1턴 이벤트, 영천 진행 경로.
  • Python 회귀: 고정 ID 이동·누락·중복 및 오프닝 대사 관련 검증.
  • 문서: API 구현 경로 대조, 상대 파일 링크·앵커, 검색·필터·모바일 배치 확인.

이 문서 최신화 작업에서 전체 게임 테스트를 다시 실행했다는 뜻은 아닙니다. 검증된 경로에서 AST API 누락이 없다는 결과도 원본의 모든 호출을 지원한다는 의미는 아닙니다. API 명세에는 미지원 원본 연동과 model.unit() 참조 생성의 현재 제한을 별도로 기록했습니다.

./gradlew --no-daemon :engine:test :core:test :desktop:classes \
  :android:compileDebugKotlin :verification:compileKotlin \
  :verification:verifyAllHeadless

현재 제약과 후속 범위

  • 시나리오용 Lua 실행기와 독립적인 코루틴 재개·저장 계약은 아직 없습니다. 전투 규칙용 Lua는 별도 구현되었습니다. 남은 stage/model/unit API는 기존 core 디스패처에 있습니다.
  • 원본 비교·수입용 도구는 선택적으로 외부 복원 프로젝트를 사용하지만 일반 빌드의 의존성은 아닙니다.
  • YAML에 항목을 추가해도 새 이미지나 새 효과 규칙이 자동 생성되지 않습니다. 자동 ID 배정·라이브 재로딩·시각적 편집기도 제공하지 않습니다.
  • 장비 효과 그룹은 specialType/itemType으로 조회하며, 소비 아이템 ID 범위와 compact ID 규칙을 유지합니다.
  • 전체 캠페인의 모든 분기 완주와 모든 화면의 픽셀 일치를 보장하지 않습니다.

이번 통합 검증

콘텐츠 패키지 분리, 이름 있는 gvars의 저장 호환, Lua 규칙의 장수·착용 장비 연결과 새 전투 재로딩을 검증했습니다. 공격·피격의 POWER/DAMAGE 제한, 난수·상태 변경 차단, 특수 물리 공격 경로와 공격 마법의 회귀 테스트를 포함합니다. Android는 컴파일 검증이며 실제 기기 실행 검증을 뜻하지 않습니다.
