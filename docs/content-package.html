임충전의 실행 콘텐츠와 공통 기반

현재 게임은 수호전 외전: 임충전이다. 조조전의 캠페인 시나리오·대사·인물·아이템·책략 데이터는 실행 패키지에서 제거했다. 공통 전투 규칙과 화면 자산을 활용해 임충전만 실행한다.

실행 패키지

대상현재 원본과 범위
게임 진입·저장content/game.yaml: 게임 ID linchong, 시작 R_90/scene0, 주인공 512, 기본 전투 S_90, 저장 namespace linchong-native-jojo-v1.
시나리오·대사content/scenarios/: R_90~R_97과 S_90~S_97의 16개 모듈, manifest.json, dialogue-text.json. 원작 R/S 모듈과 common/train 모듈은 포함하지 않는다.
인물·물체content/characters/0512.yaml~0575.yaml: 임충전 인물, 전장 물체, 내레이터 64개.
장비·기술·상점content/equipment/ 28개, skills/active/0100.yaml~0109.yaml 10개, shop/0058.yaml~0065.yaml 8개. 장면 번호 90~97과 상점·전장 인덱스 58~65는 별도 식별자다.
작성 원본·생성기content/examples/linchong/의 캠페인 JSON·규칙·원본 그림·ID 매핑과 scripts/의 임충전 생성기. 실행 파일은 content/의 정식 카탈로그와 scenarios에서 빌드한다.
진행 상태content/variables/globals.yaml의 linchong.* 변수. 저장 키와 배포된 숫자 ID를 유지한다.

남아 있는 공통 기반

병과·병종(arms/posts), 공격·효과 범위(hitarea/effarea), 효과 애니메이션, 지형·상태 설정, 수동 효과 정의와 의미 이름 매핑은 전투 계산에 필요한 공통 데이터다. 이 목록은 플레이 가능한 원작 캠페인을 등록하지 않는다. 스킬 배정과 장비 효과 카탈로그는 현재 비어 있다.

content/assets/에는 임충전 그림과 공통 UI·아이콘·전투 효과·음원이 있다. content/resources/i18n/는 시스템 문구다. 런타임이 공유하는 경로와 효과 ID는 참조를 확인하고 변경해야 한다. 공통 화면·효과 자산을 전부 삭제하면 임충전도 표시할 수 없다.

engine/는 콘텐츠를 모르는 실행 기반이고, core/는 화면·전투·콘텐츠 로딩을 담당한다. 저장소의 과거 검증 코드나 개발 기록에 남은 원작 이름은 현재 배포 콘텐츠 목록을 뜻하지 않는다.

희소 ID와 빌드

YAML ID는 0 이상의 정수이며 연속일 필요가 없다. 빌드는 최대 ID까지 배열을 만들고 빈 자리를 JSON null로 기록한다. 런타임 조회는 빈 자리를 없는 항목으로 처리하며 인물·장비·기술 목록에 가짜 항목을 노출하지 않는다. 빈 카탈로그 디렉터리는 빈 배열로 생성한다. 기존 ID를 다시 매기면 시나리오·장비·저장 참조도 함께 바뀌므로 번호를 유지한다.

빌드는 core/build/generated/game-content/에 테이블을 생성하고 maps/data/에 패키징한다. AST는 별도 시나리오 빌드가 생성한다. 자산 패키징은 content/assets의 상대 경로를 유지한다. 생성 파일을 직접 편집하지 않는다.

./gradlew :core:compileGameContent :core:processResources
python3 scripts/validate_linchong.py
python3 scripts/smoke_linchong.py
./gradlew :desktop:run --args="--scenario=R_90"

삭제한 콘텐츠가 오래된 빌드 산출물에 남아 있다면 ./gradlew clean 후 다시 빌드한다. 원작 비교를 전제로 한 과거 검증 도구는 임충전 패키지 검증 명령과 구분한다.

기존 학습 문서 읽기

기존 제작 교실과 API 가이드의 R_00·R_01·S_00, 인물 0, 원작 아이템 이름은 이전 패키지를 대상으로 한 예제다. 해당 파일은 현재 제공되지 않는다. 현재 파일을 수정할 때는 임충 512, 철창 60, 기술 100~109, R/S_90~97과 실제 manifest·대사 ID를 확인한다. 새 동료의 ID는 512처럼 이미 사용 중인 번호를 재사용하지 않는다.
