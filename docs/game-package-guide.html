게임별 규칙 확장 계약 v1 — 이벤트·효과·내공 회복 예제·저장

무엇이 달라졌나요?

게임 설정

game.yaml → game-package.json → 시작 장면·주인공·저장 공간·전투 연결·데스크톱 창 제목.

원본과 자산

14개 게임 테이블과 시스템 문구·번역·실행 자산을 content에서 관리합니다. 일반 빌드는 외부 복원 프로젝트를 읽지 않습니다.

효과 이름

전투 규칙 → 효과 이름 → 콘텐츠의 숫자 ID → 인물이 가진 스킬. 기존 효과를 다른 ID에 연결할 수 있습니다.

변경의 범위

전투 계산과 효과 적용은 core가 담당합니다. 제공된 이벤트·효과 범위에서는 외부 Lua로 장수·장비의 동작을 정의할 수 있습니다. 새 화면·장비 슬롯·지원하지 않는 효과는 core 확장이 필요합니다. 전체 게임 패키지의 런타임 교체는 아직 지원하지 않습니다.

1. 다른 게임의 시작 설정

content/game.yaml을 편집합니다. 아래는 기존 시나리오 구조와 인물 0을 재사용하는 최소 변경 예입니다. 실제 이야기·인물·자산도 뒤 절에서 교체합니다.

id: yitian
title: 의천도룡기
startModule: R_00
startScene: scene0
resumeScene: scene1
protagonistId: 0
saveNamespace: yitian-game
defaultBattleModule: S_00
battleModules:
  R_00: S_00
  R_01: S_01
  # 기존 연결을 계속 사용할 경우 나머지 매핑도 유지
  1. startModule과 defaultBattleModule을 scenarios/manifest.json에 등록합니다. 시작/복귀 함수도 해당 모듈에 존재해야 합니다.
  2. protagonistId는 characters의 기존 인물을 가리킵니다. 새 주인공을 만들 경우 해당 YAML부터 등록합니다.
  3. battleModules는 장면 → 전투의 명시적 대응입니다. 하나의 전투 대상은 한 장면에만 연결합니다. 복귀는 이 대응을 역으로 찾습니다.
  4. saveNamespace를 새 값으로 바꾸면 기존 조조전 저장과 분리됩니다. 배포 후 이름을 바꾸면 이전 저장 공간이 자동 이전되지 않습니다.
  5. ./gradlew --no-daemon :core:processResources :desktop:classes 후 재실행하여 창 제목·새 게임 시작·저장/불러오기를 확인합니다.

현재 R_/S_ 접두사와 scene 숫자 체계는 여러 표시·진행 경로에서 여전히 의미를 가집니다. 설정에서 연결을 바꿀 수 있지만 임의의 모듈/함수 명명까지 범용화한 것은 아닙니다. Android 앱 이름·아이콘·applicationId는 플랫폼 배포 설정을 별도로 수정합니다.

2. 파일 위치를 고릅니다

정의작성 위치구조
기존 인물·장비·스킬characters, equipment, skills/*id와 이름 있는 필드의 개별 YAML
병과·병종arms/*.yaml, posts/*.yaml각각 40 / 80개. schema.json의 필드명과 타입 사용
공격·효과 범위hitarea/*.yaml, effarea/*.yaml각각 33 / 15개. 오프셋/범위 정의
상점shop/*.yaml99개 상점 항목
전역 테이블config.yaml, gameConfig.yaml기존 런타임 설정 테이블. game.yaml의 게임 패키지 설정과 다름
마법 애니메이션effects/animations.yaml64개 효과의 원본 호환 배열. 프레임 항목은 정수 6개
시스템 문구·번역resources/i18n/system-messages.json, resources/localization/*기존 메시지 키 유지. ko/en 문장과 번역 패치
이미지·지도·음원assets/*경로가 런타임 리소스 경로가 됨. maps·audio·title 등 기존 분류 유지
시나리오·배치·대사scenarios/*Python·manifest·대사 JSON. 전투 배치는 아직 Python 사전 목록

기존 YAML의 누락·중복 ID·미등록 필드·참조 검증을 유지합니다. 새 필드는 schema.json과 소비 코드를 함께 연결해야 합니다. config/gameConfig의 중첩 원본 호환 구조와 애니메이션 배열은 엔진의 새 범용 규칙 언어가 아닙니다.

병종 설명 수정 예

# content/posts/0000.yaml의 기존 항목을 수정
name: 무당 제자
intro: 검술과 내공을 함께 수련한 제자입니다.

위 두 줄로 파일을 덮어쓰지 말고 기존 id·능력 필드를 유지하세요. compileGameContent 후 화면에서 이름·설명을 확인합니다. 기존 번역 패치가 동일한 원문에 적용될 수 있으므로 resources/localization도 함께 확인합니다.

3. ID와 효과를 분리합니다

규칙: magicRepeat매핑: magicRepeat → 16스킬 정의: 16

core는 직접 skills[16]을 선택하는 대신 SkillEffects.id("magicRepeat")를 조회합니다. 매핑은 실행 도중 변경되지 않으며 빌드·재실행이 필요합니다.

# content/rules/skill-effects.yaml
magicRepeat: 16
lifeSteal: 238
  1. 새 스킬 ID를 먼저 skills/passive에 연속된 ID로 등록합니다.
  2. 재사용할 효과의 매핑 값을 새 ID로 변경합니다. 예: 신규 ID 334를 등록했다면 magicRepeat: 334.
  3. 인물 배정·장비 효과 등의 skillId 참조도 새 ID로 변경합니다. 매핑만 바꾸면 예전 ID를 가진 인물은 해당 효과를 잃습니다.
  4. 컴파일과 전투 테스트로 실제 발동·비발동 및 저장 복원 영향을 확인합니다.

효과 이름을 새로 적는 것만으로 새로운 알고리즘이 생기지 않습니다. 기존 효과를 재배치하거나 같은 동작을 다른 작품에서 재사용하는 설정입니다. 일부 일반 능력 보정은 스킬 정의의 argument/incType 등도 함께 해석합니다.

능동 책략의 별도 이름 공간

# content/rules/magic-effects.yaml
typeRestoreAction: 22       # magic.type 코드
categoryWhiteTiger: 29      # magic.category 코드
spellSmallSupply: 39        # magic.id

type/category/spell은 서로 다른 ID 공간입니다. 기존 능동 책략 YAML의 type/category/id와 함께 맞춰야 합니다. 패시브 ID를 여기에 혼용하지 않습니다. 빌드는 core가 사용하는 효과 이름의 누락을 검사하고 잘못된 참조를 거부합니다.

4. 자산을 교체하고 패키징합니다

content/assets 아래 파일을 동일 경로로 복사합니다. *.rgba.gz는 저장소 크기를 줄인 무손실 프레임버퍼이며 packageContentAssets가 *.rgba로 해제합니다. PNG/JPG/음원/JSON은 그대로 복사합니다. 같은 출력 경로를 만드는 rgba와 rgba.gz를 동시에 두면 오류입니다.

기존 atlas·manifest·텍스처 키 연결을 유지해야 합니다. 이미지 파일 이름만 바꿔서는 로더가 자동 발견하지 않습니다. 라벨 캐시는 텍스트와 맞는 항목으로 갱신해야 하며, 새 자산의 편집기나 일반 글꼴/라벨 생성기는 이번 변경에 포함되지 않습니다.

content/scenarios/compatibility는 복원된 조조전 분기와 동일하게 실행하기 위한 로컬 바이트코드입니다. 새로 작성하는 게임은 이 폴더 없이 직접 작성한 Python 제어 흐름을 사용해도 됩니다. 원본 Cocos 비교/수입용 도구는 계속 tools에 있지만 일반 빌드의 의존성이 아닙니다.

# 일반 빌드: 외부 복원 프로젝트 불필요
./gradlew --no-daemon :core:processResources :core:test

# 선택적 원본 비교/수입 작업에서만 경로 제공
./gradlew -Pjojo.legacyAssets=/path/to/cocos/assets :core:verifyTerrainLayerAssets

5. 검증 범위와 남은 규칙

이번 이전에서 14개 테이블의 디코딩 값과 기존 런타임 자산을 비교합니다. Meff.bin은 JSON 직렬화 표현이 달라질 수 있지만 디코딩된 애니메이션 값은 동일해야 합니다. 엔진·코어 테스트와 헤드리스 회귀를 함께 실행합니다.

python3 -m unittest tools.test_package_content_assets tools.test_stable_dialogue_ids
./gradlew --no-daemon :buildSrc:test :engine:test :core:test \
  :desktop:classes :android:compileDebugKotlin \
  :verification:compileKotlin :verification:verifyAllHeadless

장비 itemType 분류, 255 같은 센티널, 전투 슬롯 규칙, 피해 공식·타깃 코드·UI 레이아웃은 아직 기존 전술 게임의 계약입니다. 같은 규칙의 다른 작품은 콘텐츠를 교체하여 구성하고, 전혀 새로운 전투/성장 시스템은 별도 확장 구현이 필요합니다.
