01

준비하고, 원본 게임부터 실행하기

이 절의 목표는 수정하기 전에 게임 창이 한 번 정상적으로 열리는 것입니다.

도구

편집기

일반 텍스트와 코드를 저장할 수 있는 편집기를 사용합니다. 워드프로세서나 서식 있는 메모 문서는 사용하지 않습니다. 파일 인코딩은 UTF-8입니다.

실행 환경

JDK + Python

프로젝트의 Java 대상 버전은 17입니다. JDK 17 이상 중 번들 Gradle과 호환되는 버전을 사용합니다. Python은 python3 명령으로 실행돼야 하며 도구는 3.9 이상의 문법/API를 사용합니다.

처음 한 번

다운로드와 SDK

첫 빌드는 Gradle·라이브러리를 받아 인터넷이 필요합니다. Android 작업은 SDK 36이 필요합니다. Gradle 구성에서 SDK 오류가 나면 아래 SDK 안내를 따릅니다.

Gradle은 빌드를 대신 수행하는 도구입니다. 별도로 전역 설치하지 않고 저장소의 gradlew를 사용합니다. 환경 설치는 Gradle 공식 Java 호환표, Python 공식 설치 파일, Android 공식 개발 도구를 참고합니다. 저장소의 Gradle Wrapper 버전은 9.7.0이며, 인터넷 문서의 최신 버전과 다를 수 있습니다.

이 실습의 실행 기준

명령과 창 실행은 현재 저장소에서 검증하는 macOS 데스크톱을 기준으로 합니다. Windows/Linux에서는 셸·경로·JVM 시작 인자 조정이 필요할 수 있습니다. 특히 desktop의 -XstartOnFirstThread는 macOS용입니다. Android 설치·배포는 마지막 확장 과제로 둡니다.

  1. 게임 프로젝트 폴더를 준비합니다. README.md, gradlew, content/, core/가 함께 보이는 폴더가 프로젝트 루트입니다. Git을 사용하지 않으면 이 폴더의 복사본을 먼저 만드세요.
  2. 터미널을 엽니다. 터미널은 명령을 글자로 입력하는 창입니다. cd 뒤에 프로젝트 폴더를 끌어놓고 Enter를 눌러 그 폴더로 이동할 수 있습니다. 아래 /프로젝트/경로/jojo는 실제 경로로 바꿉니다.
터미널 · 프로젝트 위치와 도구 확인 · sh
cd "/프로젝트/경로/jojo"
pwd
ls
java -version
python3 --version
./gradlew --version

pwd는 현재 폴더, ls는 그 폴더의 파일 목록을 보여줍니다. ./는 현재 폴더라는 뜻입니다. command not found가 나오면 게임 파일보다 해당 도구 설치·경로를 먼저 확인하세요.

터미널 · 기본 게임 실행 · sh
./gradlew :desktop:run

첫 실행은 다운로드 때문에 오래 걸릴 수 있습니다. 다운로드 진행 중에는 기다립니다. 게임 창이 열리면 새 게임을 시작해 대사 확인과 입력을 시험합니다. :desktop:run은 게임을 닫기 전까지 계속 실행 중으로 표시됩니다. 다른 빌드 명령을 실행하려면 게임 창을 먼저 닫습니다.

설치부터 처음이라면: 도구 준비 순서
  1. Temurin 공식 JDK 17 다운로드에서 운영체제와 CPU에 맞는 JDK 설치 파일을 받습니다. JRE가 아니라 JDK를 선택합니다. Mac의 “이 Mac에 관하여”에서 Apple 칩인지 Intel인지 확인할 수 있습니다.
  2. 설치 프로그램을 실행한 뒤 터미널을 새로 열고 java -version을 확인합니다. 여러 JDK가 설치돼 있으면 사용할 버전을 선택해야 할 수 있습니다.
  3. Python 공식 설치 파일을 설치하고 새 터미널에서 python3 --version을 확인합니다. 기존 정상 설치가 있으면 다시 설치할 필요는 없습니다.
  4. 텍스트 편집기에서 “폴더 열기”로 프로젝트를 엽니다. 줄 번호·들여쓰기가 보이는 코드 편집 모드를 사용합니다.
  5. ./gradlew --version을 실행합니다. 첫 다운로드가 끝나고 버전 정보가 나오면 기본 준비가 된 것입니다. 이어서 게임을 실행합니다.

명령이 실패하면 메시지에 나온 도구부터 해결합니다. 앱이 실행되기도 전에 콘텐츠 파일을 바꿔 오류 원인을 섞지 않습니다.

Android SDK 오류가 나온다면

Android Studio의 SDK Manager에서 SDK Platform 36을 준비하고 SDK 경로를 확인합니다. 프로젝트 루트의 local.properties에 아래처럼 실제 경로를 적습니다. 이 파일에는 각 컴퓨터의 경로를 쓰므로 Git에 올리지 않습니다.

local.properties · 경로를 실제 값으로 교체 · properties
sdk.dir=/Users/사용자이름/Library/Android/sdk

Android SDK가 없는 상태의 SDK location not found는 YAML 문법 오류가 아닙니다. 사용 환경을 준비한 뒤 같은 명령을 다시 실행하세요.

Git을 이미 사용한다면 실습 브랜치 만들기
선택 · 새 작업 공간 만들기 · sh
git switch -c tutorial/my-first-game

브랜치는 같은 저장소 안에서 변경 내용을 따로 관리하는 이름입니다. 이미 같은 이름이 있으면 다른 이름을 쓰세요. 처음 배우는 분은 폴더 복사본만으로 시작해도 됩니다.

파일 지도와 ID 연결 관계

폴더는 요소를 분류하고, ID는 요소 사이를 연결합니다. 파일명·이름·ID는 서로 다른 역할입니다.

폴더 지도 · text
jojo/
├── content/                  ← 내가 작성하는 원본
│   ├── game.yaml             게임 제목·시작·저장 공간
│   ├── characters/           인물
│   ├── equipment/            장비·소비 아이템
│   ├── skills/               능동·패시브·배정·장비 효과
│   ├── arms/ · posts/        병과·병종
│   ├── hitarea/ · effarea/   공격·효과 범위
│   ├── shop/                 상점
│   ├── variables/            이름 있는 gvars
│   ├── rules/                효과 매핑·규칙·Lua 등록부
│   ├── scenarios/            Python·대사 JSON·manifest
│   ├── assets/               이미지·지도·음원
│   └── resources/            번역·시스템 문구 등

테이블별 ID는 0부터 연속이어야 합니다. 현재 인물은 0~511이므로 첫 추가 ID는 512입니다. 이후 다른 사람이 추가했다면 폴더의 마지막 ID를 다시 확인하세요. 중간 ID를 삭제·재사용하면 저장과 참조의 의미가 달라집니다. 임의로 9999를 추가하지 않습니다.

schema.json은 사용할 수 있는 필드의 이름·타입·필수 여부를 적은 규격서입니다. 초보자는 모든 규격을 암기하기보다 가장 비슷한 기존 파일을 복사하고 필요한 값만 바꾸세요.

04

YAML 읽고 쓰기: 데이터를 만드는 기본 언어

YAML은 “항목 이름: 값”으로 설정을 적는 텍스트입니다. 이 절을 이해하면 인물·장비·규칙 등록의 대부분을 읽을 수 있습니다.

attack:45# 기본 공격 능력 값
키: 프로그램이 아는 항목명콜론 뒤 공백값: 여기서는 정수주석: 사람을 위한 설명
YAML의 문자열·정수·목록·매핑 · yaml
# 설명용 예제입니다. 아래 항목을 한 파일에 전부 붙이지 않습니다.
name: "기사 아린"       # 문자열
attack: 45              # 정수: 따옴표 없음
skillEffects: [106]     # 목록: 여러 ID를 담을 수 있음
learnLevels:            # 매핑: 다른 키 아래에 값이 들어감
  "0": 1                # 병종 0 → 습득 레벨 1
  "1": 1

이렇게 작성합니다

올바른 형태 · yaml
attack: 45
name: "검: 초급"
learnLevels:
  "0": 1

이렇게 쓰면 오류입니다

따라 쓰지 않을 오류 예제 · yaml
attack: "45"     # 정수 자리에 문자열
attack: 50       # 같은 키를 두 번 작성
learnLevels:
"0": 1           # 안쪽 항목의 들여쓰기 누락
extraPower: 10   # 규격에 없는 필드

ATTACK / HIT + DAMAGEDamageModifier계산된 HP 피해의 가산 보정

ctx.actor는 공격자, ctx.target은 피격자, ctx.owner는 현재 규칙이 붙은 장수입니다. HIT에서는 owner가 방어자입니다. POWER/DAMAGE는 AI 예상 계산에서도 반복 호출될 수 있으므로 상태를 변경하거나 난수를 사용하지 않습니다.

규칙 계산 연습

아래는 예제 Lua의 산술만 보여줍니다. 실제 게임의 방어력·지형·스킬을 포함한 피해 공식이나 전투 예측기가 아닙니다.

POWER: floor(입력 × 0.2)를 더함

80 + 16 = 96

DAMAGE: 입력 범위 안에서 최대 3 감소

20 − 3 = 17
Lua의 범위와 다시 읽는 시점

파일 변경은 새 전투가 생성될 때 반영됩니다. 진행 중인 전투는 기존 소스를 유지합니다. 파일·네트워크 접근이나 실행 간 Lua 전역 상태 보존은 제공하지 않습니다. 무한 반복·과도한 실행은 제한됩니다. 공격 마법의 HP 피해를 지원하지만 반사·반동 같은 2차 피해, 회복·상태 전용 마법은 새 공격 이벤트가 아닙니다. 전체 시나리오가 Lua로 바뀐 것도 아닙니다.

예제를 끄려면 게임을 닫고 외부 폴더 지정 없이 기본 실행합니다. 환경 변수 JOJO_RULES_DIR를 설정했다면 현재 셸에서 unset JOJO_RULES_DIR로 해제합니다. 예제 폴더 수정 자체는 기본 등록부를 활성화하지 않습니다. 더 많은 효과·제한은 Lua 상세 가이드를 확인하세요.
