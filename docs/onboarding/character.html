실습 A · 기존 인물을 조금 강하게 만들기

characters/0000.yaml의 아래 두 값을 수정합니다. 원래 값은 attack 41, maxHitPoints 102입니다.

부분 수정 · 인물 0의 기본 능력 · yaml
attack: 45
maxHitPoints: 120

빌드 후 새 게임에서 인물 정보를 비교합니다. 최종 HP가 반드시 120으로 표시되는 것은 아닙니다. 실제 능력치는 병종·레벨 성장·장비 등으로 계산됩니다. 같은 조건에서 기본값을 바꿨을 때 변화가 생기는지 확인합니다. 저장된 능력치가 덮어쓸 수 있으므로 첫 실습은 기존 세이브 대신 새 게임으로 시험합니다.

그림 ID는 인물 ID와 다릅니다

필드뜻초보자 권장 작업
face초상화 참조기존 인물 파일의 실제 값을 재사용
mapAvatar거리·궁전 등의 캐릭터 표현기존 mapAvatar를 복사해 확인
battleAvatar병종·진영과 함께 해석되는 전투 그림 코드기존 값을 유지. PNG 파일명과 같다고 가정하지 않음

새 인물 512 등록과 연결

  1. 현재 characters의 마지막 ID가 511인지 확인합니다. 0000.yaml을 0512.yaml로 복사합니다.
  2. 복사본에서 id를 512, name을 “정찰병 리아”로 바꿉니다. 처음에는 기존 face/mapAvatar/battleAvatar 값을 그대로 재사용합니다.
  3. :core:compileGameContent로 검사합니다. 성공해도 아직 동료 목록이나 전장에 자동 등장하지 않습니다.
  4. 실제로 실행되는 R 시나리오 함수에 아래 합류 호출을 추가합니다. 이 페이지의 선택지 실습의 Python 들여쓰기를 익힌 뒤 진행하세요.
  5. 전투 배치가 필요하면 S 시나리오의 기존 아군/우군 항목 하나의 id를 512로 바꿔 검증합니다. 좌표·진영·나머지 필드는 유지합니다. 기존 인물을 대체하면 그 인물의 시나리오 조건도 영향을 받을 수 있으므로 실습 복사본에서만 시험합니다.
부분 수정 · 나머지 필드는 복사한 값을 유지 · yaml
# 복사한 content/characters/0512.yaml의 일부
id: 512
name: "정찰병 리아"
intro: "북쪽 숲의 길을 잘 아는 정찰병."
실제로 실행되는 장면 함수 안에 추가 · python
model.unitJoin(512, 0, 0)

현재 시작 시 자동 편성의 일부 호환 경로는 0~511을 가정합니다. 새 인물은 자동 선택을 기대하지 말고 합류·배치를 명시적으로 연결해야 합니다. 전체 신규 인물 수용 범용화는 별도 검토 대상입니다.
