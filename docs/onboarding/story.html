대사 ID는 문장 순서가 아니라 영구 식별자입니다

각 stage.say 호출에는 전역에서 고유한 ID가 필요합니다. 같은 문장을 두 곳에서 말해도 호출별 ID를 다르게 만드세요. 기존 ID를 줄 순서에 따라 다시 매기지 않습니다. 중복 ID·누락된 문장·사용되지 않는 카탈로그 항목은 AST 내보내기에서 오류가 될 수 있습니다.

현재 Python의 범위

게임은 CPython으로 .py를 직접 실행하지 않습니다. 빌드에서 AST라는 구조 데이터로 바꾼 뒤 Kotlin 실행기가 지원 문법과 게임 API를 처리합니다. 임의의 Python 라이브러리·파일 읽기·외부 패키지를 넣지 않습니다. 사용할 호출은 Python API 명세에서 확인합니다.

answer

지금 함수에서 방금 고른 선택을 처리하는 임시 값입니다. 장기적인 진행 상태로 사용하지 않습니다.

gvars["story.route"]

시나리오와 캠페인이 공유하고 저장하는 값입니다. 사용할 이름·타입·기본값을 먼저 YAML에 선언합니다.

variables/globals.yaml의 기존 variables 아래에 추가합니다. 파일의 version과 기존 선언은 유지합니다.

variables 바로 아래 · 앞 공백 2칸 유지 · yaml
  story.route:
    type: int

이 페이지의 선택지 실습의 answer = stage.choice(...) 바로 다음 줄에 아래 대입을 추가하면 선택을 기억합니다.

같은 scene1 함수 안 · if 앞에 추가 · python
    gvars["story.route"] = answer

실습 B · 한 번 고른 경로를 다시 묻지 않기

이 페이지의 선택지 실습에 추가했던 블록 전체를 아래로 교체합니다. 아래에 덧붙이면 같은 대사 ID가 중복됩니다. 앞 절에 등록한 세 문장을 그대로 사용하므로 카탈로그는 다시 추가하지 않습니다.

이 페이지의 선택지 실습 추가 블록을 교체 · 함수 안 공백 유지 · python
    if gvars["story.route"] == 0:
        stage.say('@dialogue:R_01.scene1.fantasy_gate')
        gvars["story.route"] = stage.choice('마을을 지킨다\n숲을 정찰한다', 0)
    if gvars["story.route"] == 1:
        stage.say('@dialogue:R_01.scene1.fantasy_guard')
    else:
        stage.say('@dialogue:R_01.scene1.fantasy_scout')

0은 아직 고르지 않은 상태이므로 처음에만 선택지를 묻습니다. 값이 1 또는 2이면 같은 코드에 다시 도착해도 이전 경로의 대사를 사용합니다. 빌드·재시작 후 새 게임에서 선택하고, 저장 가능한 시점에 저장한 뒤 같은 진행 상태를 불러와 확인합니다. 저장을 불러오지 않고 새 게임을 시작하면 기본값 0부터 시작합니다.

bool 변수는 YAML에서 true/false, Python에서는 True/False로 씁니다. int 변수에 문자열이나 불리언을 넣으면 오류입니다. 선언되지 않은 이름도 오류이므로 오타가 조용히 새 변수가 되지 않습니다.

확인할 것

같은 saveNamespace에서 선택 후 저장·불러오기를 수행합니다. 저장된 경로를 사용하는 실제 후속 장면을 연결한 뒤 그 분기가 유지되는지 확인합니다. 이 프로젝트에는 gvars 값을 화면에서 편집하는 전용 UI는 없습니다.

새 이름은 안정적으로 유지하세요

배포한 변수 이름은 저장 파일의 키입니다. 이름 변경·삭제에는 저장 이전이 필요합니다. 기존 숫자 주소를 읽기 쉽게 바꿀 때만 legacyId를 연결하고, 새 변수에는 불필요한 숫자 주소를 만들지 않습니다. Lua 규칙의 extensionState 자원과 gvars는 별개의 저장 영역입니다.
