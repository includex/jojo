이번 과제

상태 이상이 없는 유닛만 턴 종료에 MP를 회복하는 Kotlin 핸들러를 추가합니다. 같은 행동은 Lua로도 표현할 수 있지만, 이 과제에서는 core 확장과 등록·검증의 흐름을 배웁니다. Kotlin 파일 편집과 테스트 실행이 가능한 개발자용입니다.

1. 핸들러와 모듈 작성

core/src/main/kotlin/com/jojo/game/domain/rules/TrainingRules.kt를 만들고 다음 코드를 작성합니다. 기존 파일의 다른 핸들러는 수정하지 않습니다.

TrainingRules.kt 전체 예제 · kotlin
package com.jojo.game.domain.rules

object ClearMindHandler : RuleHandler {
    override val id = "tutorial.clearMind"
    override val supportedEvents = setOf(RuleEvent.TURN_END)

    override fun validate(parameters: Map<String, String>) {
        require(parameters.keys == setOf("amount"))
        val amount = requireNotNull(parameters["amount"]?.toIntOrNull())
        require(amount >= 0)
    }

    override fun evaluate(
        context: RuleContext,
        parameters: Map<String, String>,
        random: RuleRandom,
    ): List<RuleEffect> {
        val unit = context.units.getValue(context.actorId)
        if (unit.statuses.isNotEmpty()) return emptyList()
        val amount = minOf(parameters.getValue("amount").toInt(),
            unit.maxMagicPoints - unit.magicPoints)
        return listOf(RuleEffect.MpDelta(unit.id, amount))
    }
}

object TrainingRules : RuleModule {
    override val handlers: List<RuleHandler> = listOf(ClearMindHandler)
}

2. 전투 조립 지점에 모듈 전달

BattleScenarioAssembler.kt에 아래 import를 추가합니다. ruleConfig.createEngine 호출의 모듈 목록도 수정합니다.

부분 수정 · createEngine 호출 전체를 교체하지 않음 · kotlin
import com.jojo.game.domain.rules.TrainingRules

// createEngine의 모듈 목록 인자만 다음으로 바꾸기
request.ruleModules + luaRules.module + TrainingRules

모듈 등록은 실제로 핸들러를 쓸 수 있게 하는 단계입니다. YAML의 handler 문자열만 적는다고 Kotlin 클래스를 자동 탐색하지 않습니다.

3. 설정에서 활성화

content/rules/game-rules.yaml의 rules가 []이면 아래 목록으로 교체합니다. 기존 규칙이 있으면 항목을 추가하고 version·resources는 유지합니다.

game-rules.yaml의 rules 부분 · yaml
rules:

4. 두 조건과 상한을 검증

새 테스트 파일 core/src/test/kotlin/com/jojo/game/domain/rules/TrainingRulesTest.kt를 만듭니다.

새 테스트 파일 · kotlin
package com.jojo.game.domain.rules

import kotlin.test.Test
import kotlin.test.assertEquals

class TrainingRulesTest {
    @Test fun recoveryRespectsStatusesAndMaximum() {
        val engine = RuleEngine(TrainingRules.handlers, RuleRandom { 0 })
        val rules = listOf(RuleDefinition("test.end", RuleEvent.TURN_END,
            ClearMindHandler.id, parameters = mapOf("amount" to "2")))
        val unit = RuleUnitSnapshot("hero", 10, 10, 9, 10)
        val context = RuleContext(RuleEvent.TURN_END, "hero",
            mapOf("hero" to unit))
        assertEquals(listOf(RuleEffect.MpDelta("hero", 1)),
            engine.execute(rules, context).effects)
        val afflicted = context.copy(units = mapOf("hero" to
            unit.copy(statuses = setOf("core.poison"))))
        assertEquals(emptyList(), engine.execute(rules, afflicted).effects)
    }
}
핸들러 검증과 통합 컴파일 · sh
./gradlew :core:test --tests '*TrainingRulesTest'
./gradlew :engine:test :core:test :desktop:classes
성공하면 이렇게 보입니다

상태 이상이 없고 MP가 부족한 유닛은 자신의 진영 턴 종료에 최대 2 MP를 회복합니다. 상태 이상이 있으면 회복하지 않고 최대 MP를 넘기지 않습니다. 실제 전투에서도 두 조건을 시험합니다.

engine에 넣지 않는 이유

이 핸들러는 전투 상태와 MP 효과를 아는 게임 규칙입니다. core에 두고 조립 지점에서 등록합니다. 범용 경로 탐색이나 글자 공개 기능인 engine에 게임 이름·장비 ID 분기를 넣지 않습니다.

실습 정리

실습만 되돌리려면 YAML의 tutorial.endRecovery 항목, 조립 지점의 TrainingRules 추가와 import, 새 Kotlin·테스트 파일을 함께 되돌립니다. 일반 게임용으로 유지하려면 이름·효과 계약·저장 영향과 사용자 문서도 정리합니다.

더 자세한 책임 경계는 엔진과 게임 구조, 효과 계약은 규칙 확장 가이드를 참고하세요.
