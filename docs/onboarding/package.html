다른 세계관으로 구성하기

게임 이름·저장 공간·시작 장면을 구성합니다.

이번에 편집할 곳game.yaml · 새 모듈을 추가할 경우 manifest/대사/시나리오
배울 것새 장면과 전투를 연결할 때 필요한 등록을 익힙니다.

이번 과제

기존 콘텐츠를 이용해 다른 세계관의 제목과 독립된 저장 공간을 구성합니다. 먼저 기존 시작 장면을 유지한 설정 변경을 성공시킨 뒤 새 모듈 등록으로 확장합니다.

무협 테마

제목: 무림의 새벽
주인공: 문파의 제자
장비: 수련검
기존 효과: 회복·무공 계산

서양 판타지 테마

제목: 변경의 수호자
주인공: 신참 기사
장비: 수련용 장검
기존 효과: 불꽃 마법·방어 특성

편집: game.yaml · characters/0000.yaml실행: 앱 재시작 + 새 게임
  1. content/game.yaml에서 id·title·saveNamespace 세 값만 아래처럼 바꿉니다. startModule·startScene·battleModules 등 나머지는 유지합니다.
  2. content/characters/0000.yaml에서 name·intro를 바꿉니다. id와 그림 참조값은 유지합니다.
  3. 저장 후 기존 게임 창을 닫고 :desktop:run을 실행합니다. 새 게임을 선택합니다. 다른 저장 공간이므로 기존 조조전 세이브가 목록에 보이지 않는 것이 정상입니다.
부분 수정 · 게임 제목과 저장 공간 · yaml
# content/game.yaml — 이 세 값만 수정
id: border_guardians
title: "변경의 수호자"
saveNamespace: border-guardians-tutorial
부분 수정 · 기존 주인공의 이름과 소개 · yaml
# content/characters/0000.yaml — 이 두 값만 수정
name: "아린"
intro: "변경 마을을 지키는 신참 기사."
터미널 · 수정 리소스를 빌드하고 실행 · sh
./gradlew :desktop:run
기대 결과

데스크톱 창 제목과 인물 정보의 이름이 달라집니다. 대사 문장에 직접 적힌 “조조”는 별도 텍스트이므로 자동으로 전부 바뀌지는 않습니다. 그림도 아직 원래 그림입니다.

저장 공간 이름은 한 번 정하면 유지하세요

saveNamespace는 저장 파일을 구분하는 이름입니다. 실습 시작 때 기존 게임과 분리하고, 이후에는 같은 값을 사용합니다. 중간에 바꾸면 저장 파일이 지워진 것이 아니라 다른 저장 공간을 보게 됩니다.

무협 게임으로 연습하고 싶다면

같은 위치에 title은 “무림의 새벽”, 주인공 이름은 “연우”, 소개는 “작은 문파의 제자”처럼 작성해도 됩니다. 기술 구조는 같으며, 문파 시스템이나 내공 화면이 자동으로 추가되지는 않습니다.

R_90.py · S_90.py함수와 배치·대사 작성
manifest.json두 모듈·함수 목록 등록
dialogue-text.json새 호출의 고유 대사 ID 등록
game.yaml시작/복귀·R → S 명시 연결
  1. 사용 중이지 않은 숫자 이름을 선택합니다. 현재 목록 필터를 따르려면 R_90, S_90처럼 작성합니다. R_DEMO 같은 이름은 목록에 잡히지 않을 수 있습니다.
  2. 가까운 기존 모듈을 복사하고 필요한 초기화·종료·디스패치 함수를 유지합니다. 복사한 모든 stage.say에 새 ID를 부여하고 카탈로그에 새 문장을 추가합니다. 원래 모듈의 ID는 그대로 둡니다.
  3. manifest의 기존 항목 형식을 따르고 functions를 실제 함수 목록과 일치시킵니다. 두 칸 들여쓰기의 JSON 형식을 유지하세요. 현재 모듈 목록에는 줄 형식에 의존하는 호환 코드가 있어 한 줄 JSON으로 압축하지 않습니다.
  4. game.yaml의 battleModules에 R_90: S_90을 추가합니다. 서로 다른 R 모듈이 같은 S 모듈을 가리키면 복귀 연결 검증에서 거부됩니다.
  5. 시작부터 바꾸려면 startModule·startScene·resumeScene·defaultBattleModule을 함께 설정합니다. 시작/복귀 함수가 시작 모듈의 manifest에 등록돼 있어야 합니다. resumeScene은 기본 진입 함수 이름이며 저장한 명령 위치를 자동으로 복원한다는 뜻은 아닙니다.
  6. 승리 후 다음 장면도 설계합니다. 현재 흐름에는 R_90 다음 R_91이 존재하면 그 장면으로 진행하는 관례가 남아 있습니다. 전투 연결표가 승리 후 모든 이동을 정의한다고 생각하지 않습니다.
연결 개념 예제 · 그대로 덮어쓰지 않음 · yaml
# game.yaml 일부 예시 — 실제 R_90/S_90 등록 후 적용
startModule: R_90
startScene: scene0
resumeScene: scene1
defaultBattleModule: S_90
battleModules:
  # 기존 연결을 유지한 상태에서 추가
  R_90: S_90

이 블록만으로 새 게임이 완성되지는 않습니다. 함수·배치·카탈로그·manifest가 먼저 있어야 합니다. 자세한 API는 시나리오 API, 패키지 검증은 게임 패키지 가이드를 확인하세요.

범위 확인

게임별 인물·대사·자산·기존 규칙의 조합은 content에서 작성합니다. 새 장비 슬롯·새 화면·새 전투 방식은 core 확장이 필요합니다. 전체 content를 실행 중 교체하는 게임 선택 화면과 장면용 Lua 실행기는 아직 없습니다.
