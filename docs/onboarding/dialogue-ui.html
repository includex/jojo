이번 과제

R_01의 대사창을 조금 위로 옮기고, 본문과 화자의 크기·색을 각각 바꿉니다. 다음으로 직접 준비한 배경에 9-patch를 적용합니다. 먼저 실행 준비와 대사 수정를 마치세요.

scenario

이야기 장면의 대사창 디자인입니다.

battle

전투 중 대사창 디자인입니다. 두 프로필은 독립적이며 YAML에는 둘 다 있어야 합니다.

1. 위치와 글꼴부터 바꾸기

  1. content/ui/dialogue.yaml을 백업하고 아래 내용으로 교체합니다. 들여쓰기는 공백 두 칸을 사용합니다.
  2. panelY: 75는 패널 아래쪽을 위로 옮깁니다. 본문과 화자는 패널 Y에 각 오프셋을 더하므로 함께 이동합니다. X는 화면 기준 절대 위치입니다.
  3. 본문은 28, 화자는 32로 분리합니다. 색은 #가 주석이 되지 않도록 반드시 따옴표로 감쌉니다.
  4. 저장하고 게임 창을 닫은 뒤 아래 명령으로 다시 실행합니다. 실행 중 파일을 고쳐도 자동 반영되지 않습니다.
content/ui/dialogue.yaml · 전체 파일
version: 1
profiles:
  scenario:
    legacyRaster: false
    layout:
      panelY: 75
      textLeftX: 330
      textRightX: 342
      textOffsetY: 110
      textWidth: 600
    bodyFont:
      size: 28
      color: "#202030FF"
      borderWidth: 0
      scaleX: 1.0
      scaleY: 1.0
    speakerFont:
      size: 32
      bold: true
      color: "#653A20FF"
      borderWidth: 0
      scaleX: 1.0
      scaleY: 1.0
  battle: {}

이야기 대사창이 조금 올라가고 본문과 이름의 글자 크기·색이 달라집니다. 전투 프로필은 기존 설정을 유지합니다. 긴 문장에서 줄바꿈과 패널 밖 넘침도 확인하세요.

원본 글자 이미지와 새 글꼴

legacyRaster는 원본 복원용 글자 이미지 사용 여부입니다. 레이아웃 또는 글꼴을 하나라도 지정하면 이 경로는 자동으로 꺼집니다. 예제에서는 의도를 드러내기 위해 false를 썼습니다. 기존 값과 같은 숫자를 넣어도 사용자 지정으로 취급합니다.

2. 내 글꼴 파일 연결하기

사용 가능한 한글 TTF 또는 TTC 파일을 content/resources/ui/fonts/dialogue.ttf에 복사하고 bodyFont와 speakerFont에 각각 path: ui/fonts/dialogue.ttf를 추가합니다. 실제 확장자와 파일 이름을 맞추세요. 경로는 패키지 내부 기준이므로 content/resources/를 쓰지 않습니다. 한글을 포함하고 배포가 허용된 글꼴을 준비하세요.

TTC처럼 여러 face가 있는 글꼴은 faceIndex로 선택합니다. 이를 지정하면 bold보다 우선합니다. bold: true는 굵은 face를 선택하는 옵션이며 임의의 TTF를 강제로 굵게 만드는 기능은 아닙니다.

3. 배경과 9-patch 연결하기

  1. 테두리가 있는 PNG를 준비하고 content/resources/ui/dialogue-panel.png에 둡니다. 예를 들어 96 × 96 이미지에서 바깥쪽 16px를 테두리로 설계합니다.
  2. 아래 블록을 scenario 안에 bodyFont와 같은 들여쓰기로 추가합니다. 이 예제는 동일한 그림을 양쪽에 사용합니다.
  3. 다시 실행해서 테두리가 유지되면서 가운데가 늘어나는지 확인합니다. panelWidth와 panelHeight로 창을 키워 보고, 글이 들어가는 textWidth도 함께 조정합니다.
scenario 아래에 추가 · PNG를 먼저 준비하세요
    background:
      leftImage: ui/dialogue-panel.png
      rightImage: ui/dialogue-panel.png
      tint: "#FFFFFFFF"
      fillColor: "#202030FF"
      ninePatch:
        enabled: true
        left: 16
        right: 16
        top: 16
        bottom: 16

9-patch 값은 원본 이미지 픽셀 단위입니다. 왼쪽+오른쪽은 이미지 폭, 위쪽+아래쪽은 이미지 높이를 넘을 수 없습니다. 모서리는 유지하고 가운데와 가장자리를 늘립니다. 꼬리 모양이 있는 원본 말풍선보다 직접 만든 직사각형 패널에 적합합니다. enabled: false이면 그림 전체를 패널 크기로 늘립니다.

좌표를 읽는 법

기본 논리 화면은 1280 × 688입니다. 원점 (0, 0)은 왼쪽 아래이고 X는 오른쪽, Y는 위쪽으로 증가합니다. 창을 실제로 확대해도 YAML 좌표는 논리 화면 기준입니다. 논리 화면 크기는 고정이며 YAML에서 변경하지 않습니다.

일반 대사에서 panelY가 아래쪽 위치이고 위쪽 배치는 여기에 topOffsetY를 더합니다. 본문 그리기 Y는 패널 Y + textOffsetY, 이름은 패널 Y + speakerOffsetY입니다. 이 값은 BitmapFont.draw에 전달하는 글자의 위쪽 그리기 기준이며 글자 상자의 아래쪽 좌표가 아닙니다. 글꼴의 ascent·크기에 따라 눈에 보이는 첫 줄 위치가 달라지므로 크기를 정한 뒤 오프셋을 조정하세요.

전투에서는 기본적으로 발화 유닛을 따라 배치합니다. 고정 좌표를 디자인할 때 battle.followSpeaker: false를 지정하세요. 왼쪽/오른쪽은 화자 배치에 따른 두 대사 방향입니다. 패널 X만 바꾸면 본문·이름·초상화 X까지 자동 이동하지 않으므로 관련 X값을 함께 조정합니다.

두 프로필의 지원 속성과 화면별 값을 모두 펼친 전체 편집용 YAML 예제도 있습니다. 복사한 뒤 필요한 값부터 조정하세요.

필요한 값만 지정하면 해당 화면의 기본값을 이어받습니다. 외부 파일은 내장 YAML 전체를 대체하며 두 문서를 합치지 않습니다. version: 1과 profiles.scenario, profiles.battle가 필수입니다.

배포와 외부 설정

content/ui/dialogue.yaml은 :core:processResources에서 ui/dialogue.yaml로 들어갑니다. PNG·글꼴은 content/resources/ 아래에 넣어 같은 작업으로 포함합니다. 배포 ZIP을 만들려면 다음을 실행합니다.

배포 ZIP 만들기 · sh
./gradlew :desktop:distZip

결과는 desktop/build/distributions/에 생깁니다. 새 YAML과 자산을 넣고 배포 파일을 다시 만드세요. 프로젝트의 content 폴더만 수정해서 이미 만든 ZIP이 바뀌지는 않습니다.

내장 파일 대신 외부 YAML을 시험하려면 파일 전체를 복사하고 환경변수를 지정합니다. 외부 YAML의 이미지·글꼴 경로도 패키지 내부 자산을 가리킵니다.

외부 YAML로 실행 · sh
JOJO_UI_DIALOGUE_PATH="$PWD/content/ui/dialogue.yaml" ./gradlew :desktop:run --args="--scenario=R_01"

JVM 시스템 속성 -Djojo.ui.dialogue.path=/절대/경로/dialogue.yaml도 지원하며 환경변수보다 우선합니다. 이 속성은 실제 게임 JVM에 전달해야 합니다. Gradle 자체에만 -D를 붙이는 방식보다 위 환경변수 예제가 간단합니다. 외부 파일도 변경 후 게임을 다시 시작하세요.

문제가 생겼다면

  • 시작 오류: 키 철자, 숫자/불리언 타입, 필수 프로필 두 개, 이미지·글꼴 파일 존재를 확인합니다. 알 수 없는 키·중복 키·YAML 별칭은 허용하지 않으며 잘못된 설정은 기본값으로 조용히 대체하지 않습니다. 파일 크기 한도는 256 KiB입니다.
  • 글이 잘리거나 겹침: 크기를 줄이거나 textWidth와 panelHeight를 늘리고 textOffsetY를 조정합니다. 패널 크기 변경이 글자 배치를 자동 재설계하지는 않습니다.
  • 전투에서 위치가 고정되지 않음: battle에 followSpeaker: false를 넣고 확인합니다.
  • 색 변화가 없음: 색 문자열의 따옴표와 프로필을 확인합니다. 배경 tint는 이미지에 적용됩니다. 단색 배경은 fillColor를 바꿉니다.
  • 원래 화면으로 복귀: 백업한 YAML을 복원하고 다시 실행합니다.
